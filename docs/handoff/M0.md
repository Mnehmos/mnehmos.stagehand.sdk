# Handoff — M0 · Spec Kit bootstrap, constitution, and corpus import

Closing issue [#2](https://github.com/Mnehmos/mnehmos.stagehand.sdk/issues/2).
Roadmap: [#1](https://github.com/Mnehmos/mnehmos.stagehand.sdk/issues/1).

## What changed and why

**The repository went from two files (`LICENSE`, `README.md`) to a validating Spec Kit project
with a scaffolded monorepo.** No feature behavior was implemented, per the issue's exit criteria.

The decisions that shaped the work:

1. **The corpus was imported verbatim and is verified by hash, not by trust.** All 177 files moved
   to `docs/corpus/` preserving their relative layout, so `SHA256SUMS.txt` still validates in
   place. `pnpm check:corpus` re-verifies all 176 recorded hashes on every run and then runs the
   corpus's own validator. This means "the corpus was imported correctly" is a checkable fact
   rather than a claim in a commit message.

2. **The constitution is embedded, not retyped.** `.specify/memory/constitution.md` contains the
   exact bytes of `docs/corpus/00_CONSTITUTION.md` inside a marked VERBATIM region, wrapped with
   Spec Kit metadata and a governance section. `pnpm check:constitution` re-hashes that region
   against the corpus file. The twelve articles cannot drift by a typo nobody notices.

3. **The v2 identity scheme was reconciled, not assumed.** See the open question below — the issue
   graph's ranges did not match anything on disk, so this took real work. `v2-allocation.json`
   holds the hand-authored allocation transcribed from issues #10–#27; `tools/v2-ids.mjs` merges
   it with v1 evidence **derived mechanically** from the corpus traceability matrix. 167 surface
   rows transcribed by hand is exactly the kind of error that never gets caught.

4. **The workspace skeleton is declarative.** `docs/governance/workspaces.json` declares 14
   workspaces; `tools/workspaces.mjs` renders all 57 files (package.json, tsconfig.json,
   src/index.ts, README.md per workspace, plus the root tsconfig paths map) and verifies them
   byte-for-byte. Internal dependency edges are **derived from the v2 ledger**, not listed by
   hand, so the graph cannot silently disagree with the feature dependencies.

5. **Rules were implemented as gates, not as instructions.** `AGENTS.md` says "core may not import
   renderers, maps, or model providers". `tools/boundaries.mjs` enforces it, and
   `tests/boundaries-core.test.mjs` proves the guard rejects violating graphs — because a check
   that has only ever been observed passing is not yet a control. Both the boundary gate and the
   ID gate were deliberately violated during M0 to confirm they fail; both were observed failing
   and then restored.

## The one thing that needs a human decision

**The v2 requirement statements have no artifact of record.** Issue #1 declares canonical v2
identities `FR-168..266`, `TEST-168..229`, `T-019..111` and states that the corpus's
`FR-001..167` are superseded — but *nothing on disk contains a single `FR-168`*. The v2 ranges are
internally consistent across all 19 issues (the per-feature ranges sum exactly to 99 / 62 / 93) and
they describe the same 18 features, but they decompose differently from the corpus: 99
capability-bound requirements instead of 167 surface-bound ones.

M0 did **not** resolve this by inventing 99 requirement statements. It reserved the identities,
recorded per feature exactly which corpus evidence each v2 range must be authored from, and left
authoring to each feature's `/speckit-specify` run. That is a defensible reading of "run
feature-scoped specify→clarify→plan→…", but it is an interpretation. **If the v2 statements exist
somewhere — a prior session, a branch, a PR — import them before M1, because M1 will otherwise
author them from scratch.** Full detail in `docs/governance/V2_ID_LEDGER.md` → *Open
reconciliation items*.

Three smaller items are recorded there too: dependency drift between the corpus ledger and the
issue graph for FEAT-012/013/014/015; the `M0..M7` vs `M1..M9` milestone-name collision; and the
still-unresolved `U-002`/`U-003` licensing questions that gate `FEAT-016` distribution.

## Deferred, deliberately

- **No `build` script and no `dist/` output.** The workspace `package.json` files declare
  `exports` pointing at `dist/`, but nothing builds yet. Adding a build pipeline that compiles
  empty modules would be theater; M1 adds it when there is something to emit.
- **No engine-level `specs/` content.** `specs/README.md` explains why it is empty and what
  belongs there.
- **Not pushed to `origin`.** All work is committed locally on `main`. Pushing is the maintainer's
  call.
- **`.gitignore` is in place but `pnpm-lock.yaml` is committed** — that is intentional, CI runs
  `--frozen-lockfile`.
