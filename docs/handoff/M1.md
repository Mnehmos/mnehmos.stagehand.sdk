# Handoff — M1 · FEAT-001 Mixed-Stream Parsing & Syntax

Closes the first slice of milestone [#3](https://github.com/Mnehmos/mnehmos.stagehand.sdk/issues/3).
Feature issue: [#10](https://github.com/Mnehmos/mnehmos.stagehand.sdk/issues/10).

## What changed and why

**`packages/parser` is implemented and converged.** `FR-168..FR-174` authored, tasks `T-019..T-024`
complete, parity exits `TEST-168..TEST-170` passing. `pnpm check` green (7/7), 51 tests.

Three decisions shaped the work.

### 1. v2 was settled by deciding *when* requirements are authored, not *what*

Issue #1 declares v2 identities that supersede the corpus's per-surface Pass-9 IDs, but nothing
anywhere contains a `FR-168`. The ranges are a capability-bound re-decomposition: FEAT-001 has 6
corpus requirements against 7 slots, FEAT-006 has 1 against 5, FEAT-011 has 7 against 4. No
mechanical mapping exists, so a batch authoring pass would have produced 99 statements detached from
the features that give them meaning, checkable against nothing.

The modular KISS answer was to make authorship *per-feature and incremental* and to enforce the
identity discipline mechanically:

- **DR-001** — a feature authors its range during its own `/speckit-specify`; ranges are *reserved*
  from M0 but only *defined* once a live spec exists.
- **DR-002** — the issue graph is canonical for dependencies; the corpus values are provenance.
- **DR-003** — roadmap `M0..M7` are the tracking milestones; rebuild-plan `M1..M9` are historical.

`pnpm check:ids` now enforces DR-001: once a feature's live spec exists, its requirement set must
equal its declared range exactly — no gaps, no extras, no foreign identities — and its test and task
references must stay inside its own slice. Both schemes stay intact with a clean supersession story,
nothing is blocked, and no adapter layer was needed.

### 2. Streaming is not a second parser

`parseScript` and `StreamingParser` drive one `CompoundFolder`. Batch/stream equivalence (FR-172) is
therefore structural rather than maintained by care. A second grammar would have been the obvious
place for the two paths to drift, and TEST-170 would have had to catch the drift after the fact
instead of making it impossible.

The folder hands segments back through a cursor (`takeFinalized`) rather than returning them from
`accept`, which is what lets one object serve a batch caller wanting everything at the end and a
streaming caller wanting each piece exactly once as it completes.

### 3. Two behaviours are fail-closed on purpose

Both follow from `DIV-003`/`DIV-004`:

- **An unterminated `[` never becomes narration.** Without framing it would otherwise fall through
  as text — precisely how the recorded Virtual Classroom incident leaked `avatar.move` into speech.
  The span from that `[` onward is treated as control and never spoken.
- **An unclosed compound is unrolled in source order rather than dropped.** Fail-closed means "do not
  speak it", not "throw it away": silently discarding control would hide producer behaviour from the
  trace.

The parser **classifies and never authorizes** (Constitution I). `[root.shell rm=-rf]` parses to a
command segment; rejecting it is FEAT-002's boundary. The one place the parser consults action
knowledge is the FR-173 quarantine heuristic, where it is an input to classification, never an
authorization — which is also why quarantine is *off* when no registry lookup is supplied: without
the vocabulary, recognising a registered action is guesswork and DIV-004 forbids guessing.

   allocation file, which does not have them.
2. The live-spec range check had never executed against an actual spec before this feature landed.

## Deferred

- **Differential run of the corpus conformance harness.** Its 21 vectors were *ported* into
  `packages/parser/test/golden.test.ts`, not executed against this implementation — the harness is
  self-contained and carries its own parser. A true differential run needs an adapter that swaps its
  internals for `@stagehand/parser`. Worth doing before M7 release convergence; it would be the
  strongest available parity signal for the parser.
- **Case-insensitive or dotted-action normalisation.** Not evidenced by the corpus; not invented.
- **A per-command error-recovery mode.** `StagehandSyntaxError` currently aborts the whole parse.
  FR-174 makes an error terminal for its command or atomic group, which implies callers may want to
  isolate one bad command; no corpus evidence exists for how, so it is left alone.
